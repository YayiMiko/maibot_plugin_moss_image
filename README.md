# MaiBot MOSS 绘图

独立 MaiBot 插件：支持原文直出生图、官方 MOSS-Image Prompt Enhancer
Caption／Layout 规划，通过 ComfyUI 生图发送到 QQ，并支持图片法术解析与视觉反推。

当前版本：[v0.2.0](https://github.com/YayiMiko/maibot_plugin_moss_image/releases/tag/v0.2.0)。离线验证、服务器部署与真实 QQ 收图和画面验收分开进行。
`main` 包含未发布的二期功能，不能把版本号或离线通过当作实图验收。

[源码](https://github.com/YayiMiko/maibot_plugin_moss_image) · [更新记录](docs/CHANGELOG.md) · [开发说明](docs/development.md)

## 指令

```text
/moss 生成 成年旅人在雨后的车站等车
/moss 规划 白色小猫坐在窗边
/moss 布局 一张咖啡店海报，标题写“今日也要好好休息”
/moss 漫画 狐莉和荧争抢最后一个包子 --角色 狐莉
/moss 表情包 狐莉无语，配字“啊？” --角色 狐莉
/moss 抽卡 鸣潮角色卡缇希娅
/moss 角色
/moss 风格
/moss 解析法术
/moss 反推
```

直接 `/moss` 查看紧凑的带注释帮助；不带子命令的 `/moss <要求>` 和 `/moss 无优化` 已移除。
不提供状态、调试、任务核对或恢复指令。普通聊天提到 MOSS 不触发生成。

`/moss 风格` 二级菜单展示选择、新建和编辑操作，主菜单不罗列这些子命令：

```text
/moss 风格 千代风格
/moss 风格 新建 墨色=monochrome ink illustration,
/moss 风格 编辑 墨色=monochrome ink illustration, restrained shading,
/moss 风格 设置
/moss 风格 设置 1
/moss 风格 设置 2
```

用途设置中，`1` 为仅用于「生成」，`2` 为用于「生成、漫画、表情包」（默认）。
`/moss 规划`、`/moss 布局`、`/moss 抽卡` 始终不使用共通风格预设，反推和解析法术也不添加风格。
插件配置 `styles.default_application` 可设置未选择时的默认值：`all` 或 `generate`。
没有风格关闭指令。风格和用途选择仅影响同一用户、同一会话的后续任务；风格库共享，
新建或编辑沿用宿主对 MOSS 命令的使用权限，不授予修改宿主配置的权限。
聊天修改保存在插件私有 `styles.json`，覆盖配置中的同名风格；菜单会展示当前生效内容。

可以直接写 `夕阳洒在她身上，比例4：3`；支持中英文冒号、空格、换行及相邻标点，
也兼容 `--比例 16:9`。引号里的比例作为画面文字保留，不当作参数。
同一等价比例重复填写可以接受，多个比例冲突会明确提示，不悄悄退回默认画幅。
可用 `--尺寸 1024x1024` 指定像素。明确尺寸须为 16 倍数，
且满足配置的像素上限；不静默改尺寸。插画与漫画默认沿用配置的 3:4、1MP 策略，表情包默认方图，
换算采用 ComfyUI ResolutionSelector 的 `MP × 1024²` 定义，对齐 16。
Layout 先固定尺寸再规划，Latent 使用同一尺寸，不在采样阶段重新计算。

## 安装与配置

需要 MaiBot 1.3.x、Plugin SDK 2.8.2～2.13.x、Python 3.12+，以及可访问的
ComfyUI。宿主的群聊白名单／发送权限仍然有效。

将完整插件目录放入 MaiBot `plugins/`，按 `pyproject.toml` 安装依赖，并配置：

1. `connection.comfyui_base_url`：从 **MaiBot 所在机器** 能访问的 ComfyUI 地址。
2. `planning.model_task`／`model_name`：宿主已配置的规划模型；不会注入聊天人设。
3. `rendering`：与 ComfyUI 文件名一致的 MOSS 主模型、编码器和 VAE。
4. `styles`：仅用于生成模式的正面前缀、风格列表和默认风格。前缀默认
   `best quality, highres,`；负面提示词仍在 `rendering.negative_prompt` 中配置。
5. `vision.model_task`／`model_name`：反推专用原生多模态路由，默认沿用宿主 `vlm`；
   与生图提示词规划模型分开，不注入人设、聊天历史或工具。
6. `characters.admin_user_ids`：可编辑、删除他人 OC 的角色库管理员；默认留空，仅创建者可修改。它不是群管理员名单，不授予宿主管理权限。
7. `draw`：配置 Tavily 凭据及抽卡开关；个人审美档案 `use_profile` 默认关闭，无档案时按内置美学规则审核，见[抽卡配置与验收](docs/aesthetic-draw.md)。

[配置示例](docs/config.example.toml) 不含凭证，需要时复制到插件根目录并命名为
`config.toml`。跨机器部署不能把回环地址当成
用户电脑，插件不会启动本地 ComfyUI。仅启用文生图，图片用于法术解析、视觉反推或联网参考分析，
不是像素级图生图，也不会从历史消息或“最新图片”隐式取图。

原图缓存读取可设置 `connection.qq_cache_roots`，只允许指定的 QQ 缓存挂载根目录。
未设置时仍可使用受限 QQ HTTPS URL，不读取任意本地文件。法术解析保留原图
元数据，不调用视觉模型或自动反推；压缩后没有元数据会明确说明。

`/moss 反推` 附一张静态图或引用同一会话中的目标图片，根据可见画面输出英文绘图 tags。
它使用视觉模型推测内容，不是还原原始提示词，不叠加前缀／风格，也不会自动生图。
读取所选消息中的多张图片会提示单独指定，不会悄悄换成另一张。发送给模型前校正方向、
缩至最长边 1536 并重编码，移除原图元数据；清晰可读的画中文字按原语言保留。

## 提示词与工作流

完整官方 skill、Layout 参考和编译器随插件携带，来源、固定版本及哈希见
`vendor/provenance.json`；不依赖开发者电脑上的 Codex 安装目录。启动时验证哈希。

`/moss 生成` 直接使用用户原始描述，不调用正文优化模型，不翻译、不扩写、不转成 tags，
也不进入官方 Caption 编译。权限、重复任务、画幅和工作流校验仍然保留。
只移除指令和生效的画幅参数，保留正文的中文、标点、换行、重复词和引号内内容。
最终组合“固定前缀 + 所选风格 + 必要角色身份对应说明 + 用户原始正文”，不自动补背景或白底。
需要白底请在正文或风格中明确提供。默认千代风格包含画师词与平涂描述，不固定年龄或人数。

生成路线的 LLM 仅可用于可选角色识别，不改写正文。Danbooru 确认中文名后，只增加原名与
canonical tag 的同一身份对应说明，不将 tag 当成另一个裸角色追加。原文已有同一 tag
时不再补充；同一 tag 的多个别名合并。未确认的名字不重复追加，不注入默认外观、服装或人数。
角色识别、查询异常或超时时保留原文继续，失败不触发扩写或默认图。
关闭现有 `planning.danbooru_enabled` 后，生成模式不调用 LLM。

`/moss 规划` 强制官方 Caption，不注入上述前缀、风格或白底规则；`/moss 布局`
强制官方自然语言扩写与 Layout 布局规划，不在 JSON 外拼接前缀。
两条官方路径共用官方编译器；生成模式完全独立，官方资源本身不改。
官方 JSON 结构错误最多请求一次文字修正；官方规划模型明确拒绝、服务错误或截断
不会重试或提交默认图。生成模式不把用户输入当作模型返回执行 tags 格式或拒绝文本校验。
官方 skill 原本面向有文件与终端工具的 agent。插件保留原版资源与创作规则，但向规划模型传入无工具的 JSON 专用指令，不再要求它查找文件或运行脚本；保存文件、坐标转换和编译均由插件完成。宿主 LLM 的实际遵循和画面效果仍需实测。

Danbooru 校正独立用于用户明确点名的角色。通过 LLM 提取原文名称和候选，使用
Anima 的查询证据与类别验证，向规划器提供身份资料和外观锚点。不替换完整提示词、
不清洗自然语言或 JSON、不将候选当成确认结果，也不添加用户未点名的角色。
查询会合并已识别原名对应的已知别名与候选，优先在线核对准确标签，必要时按原名或同作品名称补检。
本地别名仅作查询线索，仍需公共接口确认角色分类；多个同名结果不会按热度猜选。
身份确认先于可选外观补充，后者超时不会丢失已确认 tag。任务记录保留候选、HTTP 状态与失败原因，
区分查无结果、同名歧义、作品不匹配、接口不可用及预算耗尽，不把这些情况统称为未确认。
候选先规范化大小写和空白再校验；候选无效或查询失败仍保留原名及作品上下文。
Caption 正文不按逗号拆分，不应用 Anima Tag 清洗器。

`workflows/moss-int8-api.json` 保留原生 MOSS INT8、`moss_image` 编码器、FLUX.2 VAE、
Flow shift 5、负分支 SLG 第 22 层，以及 Euler／sgm_uniform、50 步／CFG 3。
只修改明确绑定的提示词、尺寸、模型和采样参数，不按 JSON 顺序猜正负面节点。
无需旧版 MOSS 自定义 Loader；实际 ComfyUI 须有这些原生节点与模型。

## 任务与发送

任务按会话、用户和消息编号去重，使用独立配置快照、随机 seed 和输出目录。
每个生图任务分别保存正文 `content_prompt.txt`、前缀快照
`prefixes.json`、最终提交的 `prompt.txt`、配置、实际工作流和采样结果。GPU 提交串行，发送等待
不占采样锁；多插件的最终 GPU 排队交给 ComfyUI。
官方路线额外保存 `draft.json`、`compiled_prompt.txt`；任务记录区分 `direct-input` 与 `official-skill`。

成功只发送图片。不确定是否提交或是否送达时记录 `remote_unknown`／
`delivery_unknown`，不自动重提、重发或全局中断 ComfyUI。只有明确成功且含平台
消息 ID 的回执才算已发送。插件重载只分类旧任务，不恢复或重试它们。

群聊长法术、反推结果或风格菜单默认超过 800 字符时发送一张合并转发卡片；不明回执不改成长正文
重发。私聊／短结果直发，展示上限 32768 字符并标记省略，不影响模型输出。
发送等待默认 200 秒，SDK 内层为 190 秒；适配器、消息网关及 NapCat 的内层
等待仍由宿主控制。插件没有修改共享网关源码或重启 NapCat。

原始 LLM 返回只在插件私有 `last_llm_response.json` 保留最近一次任务，最多 4 次
调用；单条正文／拒绝各限 32768 字符，超限标记截断。新任务覆盖，迟到返回不覆盖
新任务；解析任务清空旧调用，反推任务保存本次 VLM 返回，风格和角色库操作不改动诊断。
原文直出且关闭角色校正时，本次调用列表为空，不保留上一任务的旧返回。
诊断不会自动发到 QQ，历史任务不存原始回复。

任务默认保留 30 天，仅清理过期已结束记录和对应任务目录。未知远端任务、活动
任务、损坏记录、孤立目录及链接目标保留。删除不可恢复；0 关闭时间清理。

## OC 角色预设

没有内置或自动出场角色。先新建，再通过 `--角色 名称` 明确调用；多个角色重复写参数，别名可用，重复别名归并为一个预设。

```text
/moss 角色 新建 狐莉=白发、蓝眼睛的小狐娘，狐狸耳朵
/moss 角色 服装 狐莉=白色连衣裙
/moss 角色 别名 狐莉=小狐,狐狸娘
/moss 角色 狐莉
/moss 角色 编辑 狐莉=白发、蓝眼睛、狐狸耳朵，新的稳定外观
/moss 生成 狐莉穿雨衣站在窗边 --角色 狐莉
/moss 角色 删除 狐莉
```

外观、可选默认服装、别名分别保存。服装和别名用 `名称=` 留空清除；删除不可撤销，但不影响已接任务的快照。
角色名称不含空格，最多 80 字；库上限 64 个，每个最多 8 个别名。读取共享，修改和删除按存储的创建者或配置的角色库管理员判断，不信任消息里的角色字段。
保存于私有 `characters.json`，原子写入并去重；不改宿主人设、不从聊天记录自动学习角色。
OC 名称及别名不做 Danbooru 查询，也不猜同人 tag。缺失 OC 会提示，不悄悄换角色。
原文直出只拼稳定外观与名称绑定，不自动加默认服装，避免压过换装要求；官方规划收到分离的默认服装，仅在用户没有另行指定时参考。

## 单页漫画与静态表情包

两者均调用现有规划模型并使用随插件携带的官方 skill，不影响 `/moss 生成` 的原文直出。

风格启用时，原始要求与 `selected_style` 分开交给分镜和导出模型，不先拼成一句要求。
规划器参考其视觉处理，但本次明确的人数、角色、服装、动作和文字优先，不将风格当作额外剧情。
插件在导出后将原始风格放在前面：无字表情包放在 Caption 开头，漫画及带字表情包放在 Layout 的
`summary.caption` 开头，再由官方编译器处理；整图只保留一次，不在 JSON 外拼词，也不逐格重复。
模型在正文中回显的完整风格会移到前面，不做语义删词或画师词转换。固定正面前缀仍仅用于 `/moss 生成`。
画风进入合法描述字段，不在 Layout JSON 外拼接质量 tags 或画师串。
已确认的 Danbooru 角色 tag 由插件写入身份对应说明，不依赖模型照抄；漫画及带字表情包还会
校验角色与分镜、画面项的内部绑定。同一角色的别名合并，跨格出场保留，绑定编号不进入官方 JSON 或画面文字。
未确认的候选不伪装成 canonical tag；角色识别缺少出场字段时最多修正一次，失败后保留原始要求继续规划。

- **漫画**：只做一页、一次采样。只给角色时构思短剧情；已有剧情则围绕它扩写。先规划事件、景别、出场者和文字，再转换为官方 Layout，分镜大小和形状不使用固定四格模板。默认由剧情决定 1～4 格；可说“三格漫画”或使用 `--格数 3`。格数冲突、超出范围会提示。阅读方向由用户要求或剧情计划决定。
- **表情包**：一次一张静态图，默认 1:1，支持现有比例/尺寸参数。不强制 Q 版。无文字且构图简单时生成官方 Caption；有配字或需要定位时生成官方 Layout。不要求文案就不强加文字；可以明确要求模型创作文案。

```text
/moss 漫画 三格漫画，狐莉和荧争抢最后一个包子 --角色 狐莉
/moss 漫画 狐莉说完后跑开，对白“包子是我的！” --角色 狐莉 --格数 2
/moss 表情包 狐莉无语，配字“啊？” --角色 狐莉
/moss 表情包 狐莉困得睁不开眼，不要文字 --角色 狐莉
```

用 `配字“原文”`、`对白“原文”`、`标题“原文”` 等明确给出文字，插件锁定其语言、标点和换行，不接受后续导出模型擅自改词。
内部故事和说话人保存在 `storyboard.json`，通过内部索引绑定到官方扁平的 object/character/text 项。编译前统一填回权威文字；内部编号、说话人字段及封装不进入官方 JSON。
漫画同一人物在不同格的重复出现不会被当作重复角色删除。坐标框不等于可见边框，提示词会明确要求画出边框和留白。
几何、官方 schema 和内部绑定错误各阶段最多一次文字修正；不自动重采样，不做苛刻剧情评分，不以默认图替代失败。
每次任务保存冻结角色资料、分镜计划、编辑草稿、最终编译提示词和实际工作流。文字、跨格人设及剧情表现仍需实图验收，不保证仅凭结构合法即可准确绘制。
暂不提供多页工程、参考图改表情、图生图、动图、九宫格批量、透明抠图、字体后期排版或自动恢复。

## 高美学抽卡

`/moss 抽卡 <要求>` 从维护者核验的作品渠道检索参考，用现有视觉模型审核美学并详细分析，再结合要求和已确认角色身份导出官方 Caption/Layout，直接生一张图。
通常只看一张参考，通过即停；不合格或读取失败才换，最多三张。准备默认限 180 秒，不含排队和实际生图，不会先画三张再选。
只给角色时，先随机探索不同设计题材和媒介，参考作品不必包含该角色；角色身份在最后改编时应用。有明确专题时保留专题约束。搜索为空、读取失败和真正的审美淘汰会分别提示，并保留脱敏诊断。
未指定画幅跟随参考比例；抽卡不使用“千代风格”等共通风格预设，即使用途设为“全部”也不会叠加。直接写在抽卡要求中的画风仍会保留。固定质量前缀仍仅用于“生成”。成功只发生成图，来源和结构化评语保留在私有任务资料。

个人审美档案可选且默认关闭；无需正反例即可按内置规则筛图，开启档案后才按用户锚点比较。部署和离线测试不等于真实生图或美学验收。配置与失败边界见[抽卡配置与验收](docs/aesthetic-draw.md)。
