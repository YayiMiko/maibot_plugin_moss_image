# 抽卡与模板发现

`/moss 抽卡 <要求>` 优先在 X 发现公开作品，再用现有设计媒体渠道补充；视觉模型只判断“取到的图片能否作为本次生图的模板”，不再给美学等级。通过后结合用户要求和已确认角色身份导出官方 Caption/Layout，直接进入现有 ComfyUI 与图片发送链路。一次生成一张；参考图仅用于分析，不作为图生图输入。

## 配置与使用

在 MOSS 配置页填写 `draw.tavily_api_key` 并开启 `draw.enabled`，继续使用现有规划与反推模型路由。新安装默认关闭抽卡。用户平时只需发送要求，无需上传正反例、建立档案、校准或选择参考图。

X 与现有来源共用同一个 Tavily 凭据，不需要 X API、登录浏览器或 Cookie。个人审美档案已移除；旧 `use_profile`、`profile` 字段兼容忽略，旧文件不再读取，也不会自动删除。Tavily Key 不进入任务快照、模型消息或诊断。

## 要求与创作方向

- 硬要求引用用户原文；角色身份与参考图主题分别处理。
- 仅指定角色时，画面主题、构图、媒介和色彩开放；参考作品可以描绘完全不同的人物。Danbooru 身份校验独立用于最终改编。
- 用户指定主题/媒介时，各方向及补查继续保留该主题；只给角色时允许跨题材方向（音乐海报、时尚视觉、漫画封面、科幻拼贴、游戏宣传等），制造多样性和意外性。
- 规划器一次提供三个不同方向，每个有搜索词和设计意图；任务随机选择起点，不设固定类别配额。
- 不使用纯作者名查询；作者延伸需要 X `from:` 或主页时间线，尚未接入。
- 不把角色名、作品名或 canonical tag 作为参考图必须出现的内容；不把“柔光/居中/飘带”等完整创作方案写死进检索词。
- 抽卡始终排除共通风格预设和固定质量前缀，包括风格“全部生图”设置。用户在本次要求中明确写出的画风正常保留。

## 来源与候选

X 优先，但不独占。通常搜索一次，最多补查一次，共两次 Tavily 搜索；每个作品页最多两个关联图片地址。

X 路径：

- 只接受 `/status/<id>`；拒绝 profile、trending、home、search 页。
- 用帖子页 `og:image` 与 `cdn.syndication.twimg.com/tweet-result` 确认同一帖子 ID；至少一张 `photo` 且首图可解码才算关联成功。
- `mediaDetails` 提供该帖完整图集；最多取两张不同图片，优先 `og:image`，失败再换第二张。头像、video、animated_gif、纯文字、404、登录墙均不进入评审。
- Tavily 的 `include_images` 不作为参考图；实测与帖子无稳定关联。
- 不登录、不读 Cookie、不驻留浏览器；syndication 是未文档化公共端点，失败时记录而不回退到 Tavily 图片。

现有来源：

- Pentagram `/work/`、It's Nice That `/articles/` 与 `/features/`、ArtStation `/artwork/` 与作者子域 `/projects/`、Behance `/gallery/`。
- 正文作品图优先，分享元数据仅作有限回退；记录 `image_origin`。
- 搜索去重按 canonical key：去掉 query/fragment、Behance locale 与 `/modules/`、ArtStation 用户子域、Pentagram `/story`；同一作品不再重复占名额。

内容预过滤只处理明显不适合的内容：提示词教程/模板（`prompt:`、`how to make/create/draw/design/generate`、模板占位、`[NAME]`/YCH）、无作品词的广告/产品照、新闻产品照、纯文字。作品提到 Midjourney/ChatGPT 等工具名本身不是排除理由；官方宣发或含 AI 工具名的完整作品仍可进入评审。

去重包括 status ID、图片 media ID、canonical URL、现有感知签名；同一作者或同一 IP 在候选池设软上限，避免同活动/同系列占满三次评审。

## 预算与停止条件

| 项目 | 上限 |
| --- | --- |
| 最终生成 | 一张 |
| Tavily 搜索（所有来源） | 两次，每次最多五条结果 |
| 不同作品页读取 | 六个 |
| 每作品关联图片地址 | 两个 |
| 视觉评审调用 | 三次，含无效格式或失败的调用；首张可用即停止 |
| 插件模型调用 | 八次，含可选角色识别和结构纠正 |
| 结构纠正 | 简报与导出共享一次；拒绝不触发纠正 |
| 准备阶段 | 默认 180 秒，不含等待准备锁、GPU 排队与生图 |

X syndication 不单独占“作品页”额度，但与页面读取共用同一截止时间和两个 HTTP worker。403、图片损坏等读取失败不占视觉评审张数；内容预过滤也不占视觉评审。

## 模板适用性评审

视觉模型一次调用同时判断适用性并输出蓝图，不使用 strong/acceptable/weak 等分数。

- 可用：主要构图、视觉层次、主体-背景关系、遮挡/切割、文字与留白、纹理和小标注可保留，并能替换主体/品牌/文字满足用户要求。
- 不可用：必须推倒重画、图片残缺/截图/预览、结构无法承载目标内容、与用户明确主题冲突。
- 字体字母表通常不适合加角色；纯文字/抽象海报不一律排除，但必须有具体、可见、可行的改编依据。
- 目标角色不在参考图中不是否决理由；探索建议不是硬要求；硬要求只来自用户原文与其引用。
- 不奖励品牌、热度、细节量、饱和度或精细渲染；不使用点赞/热度硬门槛。

返回字段：

- `template_usable`
- `usable_relationships`：可保留的 1-6 条设计关系
- `blocking_issues`：不可用时的具体障碍
- `required_replacements`：必须替换的主体/品牌/文字，不构成否决
- `has_target_subject`：仅观察
- `evidence`：可见证据
- `blueprint`：可用时的原图观察与可迁移设计；不可用时为空

完整的单个 JSON 代码围栏会在本地去除，再执行严格 JSON 与字段校验；重复字段、非有限数值、附带解释、多段对象、截断结果或错误候选 ID 均不通过，不调用模型修复评审。无效评审计入三次上限；正常不可用只结束当前候选；拒绝或服务不可用时停止。

## 改编与生图

规划器再做一次改编，列出保留、替换、删除与重组。用户人数、动作、服装、主题、文字优先于参考；不自动继承原图品牌、人名与文字。已验证角色 tag 由程序按身份绑定注入并去重；未验证身份保留原始名字，不猜 tag。

用户显式比例/尺寸优先，否则跟随选中参考的比例，使用现有 MP 限制并对齐 16。官方 Caption/Layout 编译与语义落点校验通过后冻结提示词，直接生图，不再经过普通扩写。未知 GPU/发送结果不自动重试。

## 诊断、保留与验收

区分简报失败、搜索不可用/无结果、作品读取失败、内容不适合、模板不可用、视觉返回无效、改编失败及超时。没有调用视觉模型就不能报告“模板不可用”。

每任务 `draw/` 保存方向、搜索过滤原因、来源路由、候选读取步骤/HTTP 状态、待尝试候选、内容标记、评审、蓝图、选图理由、改编与预算。URL 去掉查询参数和 fragment；不记录认证头、响应正文或密钥。X 帖子文本只保留截断摘要。

最近使用记录只用于避重复，不是人物画像。最多保留 128 条摘要；选中图片独立缓存最多 256MiB、七天，空闲时清理。不缓存“模板可用”结论，也不清理旧任务、角色库或输出图腾空间。旧任务的 `rating` 只作历史诊断，不迁移、不改写。

验收依次检查离线回归、真实搜索到图片解码、模板/改编模型及最终单张生图。联网读取成功不代表模板可用；离线检查或部署成功不代表完整实图验收。真实模型与生图验收按授权单独执行，明确报告已完成层级。
