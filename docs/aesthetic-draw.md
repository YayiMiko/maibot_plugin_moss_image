# 高美学抽卡

`/moss 抽卡 <要求>` 自动选择创作方向，联网寻找优秀作品，用配置的视觉模型同时评审和反推设计，再改编为官方 Caption/Layout，直接进入现有 ComfyUI 与图片发送链路。一次生成一张图片；参考图仅用于分析，不作为图生图输入。

## 配置与使用

在 MOSS 配置页填写 `draw.tavily_api_key` 并开启 `draw.enabled`，继续使用现有规划与反推模型路由。新安装默认关闭抽卡。用户平时只需发送要求，无需上传正反例、建立档案、校准或选择参考图。

个人审美档案功能已移除。旧 `use_profile`、`profile` 字段兼容忽略，旧文件不再读取，也不会自动删除。Tavily Key 不进入任务快照、模型消息或诊断；插件不会自行读取其他插件凭据。

## 要求与创作方向

- 硬要求引用用户原文，角色身份与参考图主题分别处理。
- 仅指定卡缇希娅等角色时，画面主题、构图、媒介和色彩开放；参考作品可以描绘完全不同的人物。Danbooru 身份校验独立用于最终改编。
- 用户指定“苏联革命宣传海报”等主题时，各方向及补查继续保留主题。
- 规划器一次提供三个不同的设计方向，每个有类别、设计意图和搜索词；任务随机选择起点，不强制海报/插画配额。不将角色、作品名或 canonical tag 作为参考图必须出现的内容。
- 热点可以成为灵感，但没有来源证据不能宣称当前热门；没有单独的热点抓取服务。
- 抽卡始终排除共通风格预设和固定质量前缀，包括风格“全部生图”设置。用户在本次要求中明确写出的画风正常保留。

## 候选池与补查

通常搜索一次，最多补查一次。每次最多五条作品页元数据；保留未尝试候选及各自方向，不在换来源、换方向时清空。

同方向优先尝试单作品报道，将标题明确为趋势、合集或盘点的页面后置，再考虑来源分散与近期避重复。页面类型只是排序线索，不是质量认证；条件相近的候选继续随机。读取失败后优先尝试池内其他来源；只剩失败来源时补查其他来源，保留原设计意图。图片可读但审美不合格时切换另一个允许方向补查。搜索为空时调整方向；具体主题始终保留。补查失败或为空仍回收原池候选，并恢复该作品自己的设计方向。

优先搜索 [Pentagram](https://www.pentagram.com/work) 与 [It's Nice That](https://www.itsnicethat.com/articles) 的作品报道。后者允许 `/articles/` 和 `/features/` 具体文章。ArtStation `/artwork/`、Behance `/gallery/` 为扩展来源。只接受明确的裸域名别名和路径边界，首页、分类入口和相似恶意域名不通过。来源只提供筛选线索，不认证作品优秀、作者或奖项。

使用 [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) 取得页面。Pentagram 优先读取正文作品 `figure.workMedia` 内的图片；It's Nice That 优先读取文章内关联其作品 CDN 的图片，排除导航、侧栏等区域，并合并同一图片的响应式变体。每页最多尝试两个关联地址：优先一张正文作品图，再回退至 `og:image` / `twitter:image`；其他来源继续使用页面分享元数据。没有正文图或分享元数据时，按实际存在的关联地址回退。记录 `image_origin`，不把分享封面或大尺寸自动视为优秀完整作品，也不把聚合图片强行归给无关网页。不驻留浏览器，也不依赖 Extract。

## 预算与停止条件

| 项目 | 上限 |
| --- | --- |
| 最终生成 | 一张 |
| Tavily 搜索 | 两次，每次最多五条结果 |
| 不同作品页读取 | 六个 |
| 每作品关联图片地址 | 两个 |
| 视觉评审调用 | 三次，含无效格式或失败的调用；首张合格即停止 |
| 插件模型调用 | 八次，含可选角色识别和结构纠正 |
| 结构纠正 | 简报与导出共享一次；拒绝不触发纠正 |
| 准备阶段 | 默认 180 秒，不含等待准备锁、GPU 排队与生图 |

403、图片损坏等读取失败不占视觉评审张数。所有操作服从同一个准备截止时间，不因补查无限等待。HTTP 后台线程最多两个；图像解码串行。公共 HTTPS 校验、固定认证端点、逐次重定向校验及连接地址校验继续生效。仅静态 JPEG/PNG/WebP，单图最多 8MiB、12MP。

## 自动评审与改编

视觉模型一次检查完整作品、视觉中心、构图与留白、色彩/明暗、媒介执行及适用时的文字整合。品牌、热度、细节量、高饱和或精细渲染本身都不是通过理由。截图界面、标识、残缺样机、模糊预览与不确定结果不能通过。

要求明显优秀、没有关键缺陷、符合用户明确参考主题且可改编。评审输入分开提供用户目标要求、参考主题要求及探索建议；探索建议不是新增的硬约束。不同角色、服装、人数或参考图本身没有人物不直接淘汰，关键是能否重组为目标要求。纯字体或抽象海报同样需要按实际设计与可改编性评审。通过时同次返回原图详细蓝图及 1–6 个有价值的设计关系，极简作品不硬凑数量。

完整的单个 JSON 代码围栏会在本地去除，再执行相同的严格 JSON 与字段校验；重复字段、非有限数值、附带解释、多段对象、截断结果或错误候选 ID 均不通过，不调用模型修复评审。正常否决或无效格式只结束当前候选，继续尝试剩余作品并计入三次调用上限。明确拒绝或模型服务不可用时停止；全部无效、实际否决及混合失败分别提示，不降低门槛或提交默认图。

规划器再做一次改编，列出保留、替换、删除与重组。用户人数、动作、服装、主题、文字优先于参考；不自动继承原图品牌、人名与文字。已验证角色 tag 由程序按身份绑定注入并去重；未验证身份保留原始名字，不猜 tag。

用户显式比例/尺寸优先，否则跟随选中参考的比例，使用现有 MP 限制并对齐 16。官方 Caption/Layout 编译与语义落点校验通过后冻结提示词，直接生图，不再经过普通扩写。未知 GPU/发送结果不自动重试。

## 诊断、保留与验收

区分简报失败、搜索不可用/无结果、作品读取失败、有效输入不适用、审美未通过、视觉返回无效、改编失败及超时。没有调用视觉模型就不能报告审美未通过。

每任务 `draw/` 保存方向、搜索过滤原因、来源范围、候选读取步骤/HTTP 状态、待尝试候选、评审、蓝图、选图理由、改编与预算。URL 去掉查询参数和 fragment；不记录认证头、响应正文或密钥。原始模型返回继续使用现有最近任务诊断，不建立历史原始回复库。

最近使用记录只用于避重复，不是人物画像。最多保留 128 条摘要；选中图片独立缓存最多 256MiB、七天，空闲时清理。不缓存“审美通过”结论，也不清理旧任务、角色库或输出图腾空间。

验收依次检查离线回归、服务器真实搜索到图片解码、视觉/改编模型及最终单张生图。联网读取成功不代表审美通过；离线检查或部署成功不代表完整实图验收。真实模型与生图验收按授权单独执行，明确报告已完成层级。
